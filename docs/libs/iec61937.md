# IEC 61937 transport (`iec61937`)

`iec61937` is the platform-independent carrier layer for the virtual S/PDIF
device. It has no CoreAudio, GStreamer or FFmpeg dependency. The macOS HAL
bundle and a later Linux backend can share it.

## Layers

| Module | Responsibility |
|---|---|
| `carrier` | Streaming IEC 61937 burst framing, sync recovery, null/unsupported detection, carrier word swap |
| `eac3` | E-AC-3 syncframe boundaries inside a burst, including dependent substreams |
| `truehd` | TrueHD MAT removal, access-unit reassembly across MAT codes/frames, relative timing |
| `Depacketizer` | Convenience wrapper: carrier bytes → complete codec access units |

The carrier input is the byte stream delivered by the HAL boundary: 16-bit
little-endian words. Payload bytes are returned in codec byte order; the word
swap happens once in `carrier`.

## Supported carrier modes

| Mode | Data type | Burst period | Carrier stride |
|---|---:|---:|---:|
| E-AC-3 | 21 | 24,576 B | 4 B/frame |
| TrueHD MAT | 22 | 61,440 B | 16 B/frame |

The inspected path is 192 kHz carrier and 48 kHz programme. `TrueHdDepacketizer`
takes the programme sample rate so its timing check uses the right number of
carrier bytes per audio sample (64 at 192 kHz carrier / 48 kHz programme).
Other configurations must be validated against the receiver caps before they are
advertised.

## TrueHD relative timing

The TrueHD MAT layout follows FFmpeg's `spdifenc.c`:

- 20-byte start code at payload offset 0;
- 12-byte middle code at 30708;
- 16-byte end code at 61408 in a 61424-byte payload.

Access units can cross those codes and MAT-frame boundaries. The depacketizer
reassembles them by:

1. keeping the access-unit data regions and their absolute carrier offsets;
2. reading the 12-bit access-unit length and 16-bit input timing;
3. locating the next boundary by combining zero padding, the access-unit
   candidates around the first non-zero byte, and the exact timing-to-carrier
   spacing equation.

Each `TrueHdAccessUnit` keeps the raw `input_timing`, an unwrapped
`sample_offset`, and the absolute `carrier_offset`. The payload bytes are never
resampled or rewritten.

FFmpeg's `spdifdec.c` has an E-AC-3 path but no TrueHD path, so the TrueHD side
is not an FFmpeg demuxer wrapper. The MAT constants and padding behavior were
checked against `spdifenc.c` at the FFmpeg revision used to make the fixtures.

## Fixture verification

The transport checks use the fixtures under
`platform/macos/salsa-hal/fixtures/` (generated by `make_fixtures.sh`, not stored
in Git). Run the opt-in checks with:

```sh
SALSA_TEST_SPDIF_FIXTURES=platform/macos/salsa-hal/fixtures \
  cargo test -p iec61937
```

The checks feed the carrier in 8,191-byte chunks, including odd fragmentation:

- E-AC-3: all 625 bursts are recovered; concatenated payloads equal
  `eac3_20s.ec3` byte for byte; no resync or malformed burst.
- TrueHD: all 999 MAT frames are parsed; the 23,976 access units equal the
  `truehd_20s.mlp` prefix byte for byte; every `sample_offset` equals the
  unwrapped input-timing delta; no malformed MAT frame.
- Reset: a new generation starts, partial carrier input is dropped, and every
  recovered access unit carries the new generation.

Unit tests cover synthetic fragmentation, null/unsupported bursts, invalid
lengths, E-AC-3 dependent substreams, an incomplete frame held across bursts, and
an access unit split by the MAT middle code.

## Deliberate limits

- Other IEC 61937 data types are reported as unsupported, never passed through
  as PCM.
- Only the TrueHD-in-MAT payload mode emitted by mpv/FFmpeg is accepted.
- The carrier byte order is little-endian; a big-endian backend needs an input
  adapter at the HAL boundary.
- Transport recovery is byte-exact; rendered floating-point audio is not part of
  this crate.
